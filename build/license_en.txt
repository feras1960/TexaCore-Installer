7. What the Software sends over the internet

7.1 The Software works offline. When the computer is online, the Software contacts our servers and a few other services, as listed in this section. The list describes the current version.

7.2 Licence activation and checks. When you activate the Software, and then about every three minutes while it is running and online, it contacts our servers. In the free edition it sends the free licence number, a device identifier derived from your computer's hardware, the computer name, the operating system and processor type, and the program version. For paid and trial licences it sends a fuller status message: the same items, plus the operating system version; hardware details (processor model, number of cores, memory and disk use) and how long the computer has been running; the computer's local network addresses; the status of the program's own services; the number of active users, companies and invoices and the size of the database; and the licence status, plan and active modules. Neither message contains the contents of your records, such as customer names, invoice lines or amounts. While it runs, the Software also keeps a live connection to our servers, over which it shares the licence key, the computer name, the program version and the time it came online, so that the licence shows as online and changes to your licence apply quickly.

7.3 Location. The Software does not look up its own public IP address or location. When a status message reaches our servers, we record the public IP address it came from and work out an approximate location (country and city) from that address with a lookup service (ipwho.is), which receives the public IP address. We keep the address and the location with the licence record.

7.4 Plan and licence updates. About every fifteen minutes while it is online, the Software asks our servers for the current licence state and plan catalogue (modules and limits) and applies them to your installation.

7.5 Cloud backup. While the Software is online and licensed, it uploads a backup copy of your company data file to TexaCore's cloud backup storage when the file has changed, and at least every twelve hours. Files larger than 100 MB are skipped. If you open or import a company file from another program (for example a Rashid .rsf file), the Software also uploads a copy of that original file once. The cloud backup storage keeps recent copies only. The size and availability of cloud backup depend on your plan. These copies contain your company data. We hold them as your processor and use them only to store them, to restore them if you ask, and to operate and secure the service. You can ask us to delete your cloud backups at any time by writing to info@texacore.ai.

7.6 Update checks. The Software checks GitHub's release servers for new versions and offers to download and install them. GitHub receives the request, including your IP address and the version in use.

7.7 Cloud access (optional). If you switch on cloud access, the Software registers a web address for your installation with us and opens a Cloudflare tunnel, so that you can reach your installation from outside your network. Traffic to that address passes through Cloudflare. Cloud access stays off until you switch it on.

7.8 Error reports. When the Software meets an error, it may send a technical error report to our own error-tracking server: the error message, the program version and the screen where it happened. Reports are scrubbed of access tokens, email addresses and long numbers, and do not include the contents of your records.

7.9 Features you choose to use. Some features need a cloud service, for example the AI assistant, email sending or Telegram notifications, where your edition includes them. When you use one of them, the Software sends what that request needs. The AI Features Notice at https://texacore.ai/legal/ai/ explains what is sent to AI providers.

7.10 Our servers are hosted by Supabase on Amazon Web Services in London, United Kingdom, and delivered through Cloudflare.
